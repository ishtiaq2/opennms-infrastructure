# 🔬 The Live Hot-Deploy Lab

Let's drop these bundles into your running Karaf instance and watch the OSGi Service Registry wire them together in real-time.

* 1. Start Karaf and Watch the Logs:If Karaf isn't already running, start it up.   
    Then, access the Karaf shell and tail the log so we can see what happens behind the scenes.

## In your terminal, start Karaf (adjust path if necessary)
* ~/apache-karaf-4.4.11/bin/karaf

## Once inside the karaf@root()> prompt, run:

* log:tail

## Deploy the Provider: Open a second terminal window (keep the Karaf log running in the first one). 

* Copy the Provider JAR into Karaf's auto-deploy folder:

* scp ../provider/target/provider-1.0.0.jar admin@192.168.1.120:/home/admin/karaf/
  apache-karaf-4.4.11/deploy/

* bundle:list | grep -i provider


Look at your Karaf logs! You might see a brief message that Felix processed it. The GreetingService is now secretly waiting in the JVM memory.

## Deploy the Consumer:Now, drop the Consumer JAR into the deploy folder:
* scp ../consumer/target/consumer-1.0.0.jar  admin@192.168.1.120:/home/admin/karaf/
  apache-karaf-4.4.11/deploy/

  ### Watch the Karaf logs instantly! You should see:[CONSUMER WAKING UP] Calling the provider...Hello OpenNMS Developer, this message was generated by the Provider Bundle!

* 4.Test the Zero-Downtime Hot-Swap:In your Karaf shell, 
  press Ctrl+C to stop tailing the logs. Find your Provider's bundle ID:  bundle:list | grep -i provider

Let's pretend the Provider crashed or you uninstalled it. Type this in Karaf (replace XX with your provider's ID):stop XX

Now check the logs: log:display.
Because the Provider vanished, the OSGi Service Component Runtime (SCR) immediately intercepted the event and cleanly shut down your Consumer to prevent a NullPointerException! You will see:[CONSUMER] Oh no! The Provider is gone. Going to sleep.
